## Major open work

### Authenticated join and Bluetooth data path

- P6-004 is deliberately fail-closed. The transaction coordinator and rollback groundwork exist, but production join still needs the approved peer enrollment flow, authenticated control session wired to live PAN sockets, PANU/data-plane lifecycle, and end-to-end validation.
- P7-003/P7-004 have tested TLS 1.3, certificate identity checks, exporter-bound Hello/HelloAck and pin-gated ingress/session primitives. These are not integrated into the daemon's live PAN socket/reconnect lifecycle.
- The enrollment ceremony decision is still pending: compare fingerprints in person, verify a QR using a separate trusted channel, or keep joins disabled. Do not authorize a peer based on Bluetooth trust, MAC address, advertised identity or an unauthenticated certificate claim.
- P6-006 application traffic has a runbook and software test helpers, but physical ping/TCP/UDP/DNS/Wi-Fi-isolation/cleanup acceptance is outstanding. `docs/P6-006-APPLICATION-TRAFFIC.md` is the starting procedure.
- P6-007, P6-010 and P16-001..P16-007 need manual multi-client, recovery, heterogeneous-node, and release acceptance as detailed in the hardware backlog.

### Routing, lifecycle, and diagnostics

- P8-001/P8-004 observation/route-planning models are implemented. P8-002/P8-003 need live route/address and forwarding reconciliation; P8-005 route distribution/application is not implemented. P8-006..P8-008 require both software integration and real routed Bluetooth traffic.
- P9 automatic topology policy/execution/reformation remains mostly unimplemented.
- P13-001 has startup reconciliation but not a continuous desired-vs-observed loop. BlueZ/NetworkManager restarts, adapter changes and suspend/resume remain open. P13-006 retry primitives and P13-007/008 portions are implemented, but runtime lifecycle and live diagnostics are incomplete.
- P10 CLI commands are partially implemented; remote authenticated peer inventory, complete lifecycle, detailed topology diagnostics and cross-command integration remain open.

### User interfaces, packaging, and release

- P11 TUI and P12 desktop app are still incomplete; the desktop shell is intentionally not packaged. This blocks GUI daemon/capability detection and the GUI workflows in P16-001.
- P15-002 has a reproducible software build, but clean Debian install and more-than-one-computer qualification remain. P15-003 still lacks GUI detection. P15-004 upgrade preservation and P15-005 live route/runtime cleanup need installed-system tests.
- P17 user documentation and release support matrix/gate are incomplete. Do not claim v1 readiness or broad hardware support.
- P18 Internet sharing/gateway and P19 future features remain open; P18 is explicitly after the local routed network work.
